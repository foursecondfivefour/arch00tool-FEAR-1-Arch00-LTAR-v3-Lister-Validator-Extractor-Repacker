# Внутреннее устройство

[К оглавлению](README.md) · [Формат](03-format.md) · [Безопасность](05-safety.md)

Проект состоит из одного файла `arch00tool.py`. Ниже «модули» — логические части файла, а не отдельные Python-пакеты. Используются `argparse`, `fnmatch`, `hashlib`, `os`, `struct`, `sys`, `zlib`, `dataclasses` и `pathlib`. Аннотации отложены через `from __future__ import annotations`.

## Константы и модели

- `HEADER`, `FILE_ENTRY`, `FOLDER_ENTRY` — заранее скомпилированные `struct.Struct` для трёх структур; их форматы и размеры приведены в [описании формата](03-format.md).
- `HEADER_SIZE` — 48; `IO_CHUNK` — 4 МиБ для чтения/копирования; `MAX_TABLE_BYTES` — 512 МиБ для имён; `MAX_ENTRIES` — 2 млн для каждого счётчика.
- `Arch00Error` — исключение ошибок формата и защитных проверок.
- Неизменяемый `Header`: `version`, `names_size`, `folder_count`, `file_count`, `retail`, `download`, `crc_enabled`, `guid` (сырые 16 байт).
- Неизменяемый `Entry`: полный `name`, абсолютный `offset`, `stored_size`, `unpacked_size`, `compression`.

## Разбор

- `read_exact(file, size, what)` читает заданное число байтов или выбрасывает `Arch00Error` с контекстом.
- `read_c_string(blob, offset, what)` проверяет смещение и NUL, декодирует UTF-8 с резервным CP1252.
- `parse_header(file, file_size)` читает заголовок из текущей позиции, проверяет сигнатуру, версию, лимиты и размер метаданных, возвращает `Header`.
- `parse_archive(path)` получает размер через `stat`, открывает архив, читает три таблицы и проверяет диапазоны и распределение записей каталогами. Возвращает `(Header, list[Entry], list[str])`; порядок записей — порядок таблицы файлов, а не физический порядок данных. Это важно для сопоставления замен при пересборке.

## Пути и обработка данных

- `safe_output_path(root, archive_name)` заменяет `\\` на `/`, удаляет пустые компоненты и `.`, затем запрещает пустой результат, компоненты `..`, двоеточие и абсолютные пути. Возвращает `root.joinpath(...)`; не разрешает путь через `resolve` и не проверяет символические ссылки.
- `copy_raw(archive, entry, output)` переходит к смещению и копирует ровно `stored_size` блоками, возвращая количество байтов; `unpacked_size` не сравнивается.
- `inflate_zlib(archive, entry, output)` читает ровно сохранённый диапазон, подаёт блоки в `zlib.decompressobj`, пишет результат и сверяет заявленный размер, достижение конца потока и отсутствие `unused_data`. Ошибки zlib преобразуются в `Arch00Error`. Распаковка одного входного блока может породить значительно больше 4 МиБ в памяти; блок чтения не является пределом памяти.
- `process_entry(archive, entry, output, force_raw=False)` сначала обрабатывает нулевой размер, затем выбирает raw (включая принудительный режим) или zlib для 1–9; другие непустые методы отклоняет. Возвращает число записанных байтов.
- `extract_entries(path, output_root, entries, force_raw, verbose)` сортирует записи по смещению, создаёт родительские каталоги и каждый файл через `xb`, вызывает `process_entry` и суммирует байты. При ошибке отката нет.

## Пересборка

- `archive_files(directory)` возвращает отсортированные по имени без учёта регистра обычные файлы с расширением `.arch00` в одном каталоге.
- `copy_range(source, destination, source_offset, size, context)` и `file_digest(file, offset, size, context)` потоково копируют диапазон и вычисляют SHA-256 соответственно; оба используют `read_exact`.
- `repack_archive(source_path, output_path, replacement_root=None)` возвращает `(число_записей, сумма_stored_size, число_замен)` и выполняет следующие шаги:
  1. Проверяет различные пути источника и выхода и отсутствие выхода; разбирает исходный архив, затем повторно читает заголовок и сырые таблицы.
  2. Для каждого файла проверяет, что начало данных не внутри метаданных, и при наличии `replacement_root` ищет файл по безопасно нормализованному полному имени. Замена становится raw, размеры равны размеру файла. Для прочих записей размеры и метод сохраняются.
  3. Сортирует записи по `(старое смещение, индекс)`, размещает диапазоны вплотную за таблицами и обновляет смещения (а для замен также размеры и метод). Исходный заголовок, таблица имён, записи каталогов и остальные поля записей файлов копируются.
  4. Исключительно создаёт `ВЫХОД.partial`, пишет метаданные и данные, вызывает `flush` и `fsync`. Снова проверяет заголовок и сравнивает прочитанную таблицу файлов с новой таблицей в памяти, а таблицу каталогов — с исходной. Заголовок и имена не сравниваются побайтово при проверке.
  5. Сравнивает SHA-256 каждого нового диапазона с соответствующим диапазоном исходника или файла замены; переименовывает временный файл в выход. При перехваченном исключении внутри блока записи пытается удалить временный файл.

Это проверка целостности копирования, не валидация сжатия, CRC, семантики метаданных или работы игры. Перекомпоновка убирает неописанные промежутки/хвост, а перекрывающиеся диапазоны копируются отдельно: побайтовая идентичность всего архива не обещается. Размер замены и её данные считываются в разные моменты, поэтому файлы не должны меняться во время работы.

## CLI и поток управления

- `cmd_list`, `cmd_test`, `cmd_extract`, `cmd_repack`, `cmd_test_all`, `cmd_extract_all` реализуют соответствующие команды и возвращают код завершения. Пакетные обработчики перехватывают ошибки отдельных архивов и продолжают там, где это предусмотрено.
- `make_parser()` строит `argparse.ArgumentParser`, определяет аргументы и привязывает функции через `set_defaults(func=...)`.
- `main()` разбирает аргументы, вызывает `args.func(args)`, перехватывает `Arch00Error`, `OSError`, `OverflowError` и возвращает 2. Входная точка вызывает `raise SystemExit(main())`. `argparse` обрабатывает собственные ошибки аргументов самостоятельно.
