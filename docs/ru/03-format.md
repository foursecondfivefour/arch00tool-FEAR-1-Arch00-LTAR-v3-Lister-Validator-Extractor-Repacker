# LTAR v3: модель, реализованная скриптом

[К оглавлению](README.md) · [Внутреннее устройство](04-internals.md)

Это описание прочитанного кода, не официальная спецификация. Неизвестные поля не расшифрованы; нельзя заключать, что все игры и варианты LTAR совместимы. Все числа little-endian; `I` — беззнаковые 32 бита, `Q` — беззнаковые 64 бита. Смещения — в байтах от начала файла.

## Общая схема

```text
0             заголовок: 48 байт (<12I)
48            таблица имён: names_size байт
              file_count записей файлов, по 32 байта (<IQQQI)
              folder_count записей каталогов, по 16 байт (<IIII)
              области данных по смещениям из записей файлов
```

Парсер не требует, чтобы данные следовали непосредственно за таблицами, были упорядочены или не пересекались. Он проверяет только границы каждой области; пересборщик дополнительно запрещает начала областей внутри метаданных. Промежутки и данные вне записей при пересборке не сохраняются.

## Заголовок (`<12I`, 48 байт)

| Смещение | Поле | Как используется |
|---:|---|---|
| 0 | signature | Должны быть байты `LTAR`. |
| 4 | version | Должно быть 3. |
| 8 | names_size | Размер таблицы имён, максимум 512 МиБ. |
| 12 | folder_count | Число записей каталогов, максимум 2 000 000. |
| 16 | file_count | Число записей файлов, максимум 2 000 000. |
| 20 | retail | Флаг/значение, выводится, семантика не проверяется. |
| 24 | download | Аналогично. |
| 28 | crc_enabled | Выводится; CRC не проверяется и не пересчитывается. |
| 32–47 | guid | 16 исходных байтов; выводятся hex без интерпретации порядка полей GUID. |

Парсер также проверяет, что конец всех таблиц не превышает размер архива. Ограничение 512 МиБ относится только к таблице имён, не к совокупности всех таблиц и данных.

## Имена

Таблица — массив байтов; записи файлов и каталогов содержат смещение внутри неё. Строка заканчивается нулевым байтом. Смещение должно попадать в таблицу и после него должен находиться NUL. Сначала используется UTF-8; при ошибке декодирования — CP1252 с заменой неподдерживаемых байтов. Проверяются только строки, на которые ссылаются записи; скрипт не доказывает корректность всей таблицы и не требует, чтобы смещение указывало на начало ранее выделенной строки.

## Запись файла (`<IQQQI`, 32 байта)

| Смещение в записи | Размер | Значение |
|---:|---:|---|
| 0 | 4 | Смещение имени в таблице имён. |
| 4 | 8 | Абсолютное смещение сохранённых данных в архиве. |
| 12 | 8 | `stored_size`: количество сохранённых байтов. |
| 20 | 8 | `unpacked_size`: заявленный размер результата. |
| 28 | 4 | `compression`: 0 — raw, 1–9 — zlib согласно реализации. |

Для каждого диапазона проверяется `offset <= размер_архива` и `stored_size <= размер_архива - offset`. При нулевом размере смещение может указывать на конец архива. Проверка содержимого выполняется отдельно командами `test` и `extract`, а не при простом разборе.

## Запись каталога (`<IIII`, 16 байт)

Первое число — смещение имени каталога; следующие два сохраняются как неизвестные; последнее — количество файлов этого каталога. Скрипт последовательно распределяет записи файлов между каталогами в порядке таблиц. Сумма количеств должна равняться `file_count`; выход за пределы таблицы запрещён. Полный путь составляется как `имя_каталога + обратная_черта + имя_файла`, либо просто имя файла при пустом имени каталога. Пустые каталоги остаются в списке каталогов, но отдельной файловой записи не создают. Имена могут уже содержать разделители; скрипт не интерпретирует иерархию каталогов за пределами этого соединения.
